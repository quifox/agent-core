# Agent 实例与插件生命周期

> 本文固定对象、注册、初始化与状态归属；执行钩子的参数和模型/工具循环以 [架构规范](architecture.md) 为唯一正文。

## 对象与入口

- createAgent 接收已经创建的有序插件对象，返回可执行的 Agent。插件可以用 new、普通函数或明确共享的对象构造。
- Agent 提供 stream 和 run；run 完整消费同一条 stream。输入形状由插件组合定义，运行观察通过 stream 或插件提供的出口表达。
- 注册和首次初始化的异步处理完成后，才能进入模型与工具循环；Core 不运行半加载插件。
- createAgent 同步保留候选对象；第一次消费 stream 或调用 run 时惰性完成异步注册与初始化。初始化失败保留失败结果，不自动重放可能已经产生副作用的初始化。
- 同一 Agent 的后续执行复用保留的完整插件集合及对象引用；不能只复用 Session，也不能每轮复制、重新构造或重新注册其他插件。
- Core 可以复制插件数组容器以固定最终集合，不能因此复制插件状态或把调用方持有的对象替换为别的实例。
- 注册加载结束后，运行期不增删插件或工具；外部修改原数组不是热安装。改变组合时，由调用方构造新的 Agent。
- Core 不规定所有插件都必须独占一个 Agent。复用对象意味着共享其内部状态；插件自行决定是否支持这种共享。
- 多个独立对话使用不同 Agent；本合同不提供同实例并发对话调度、全局运行 ID 或自动排队。

## 候选列表与 onRegister

- onRegister 接收本次注册的完整可变候选数组，返回 Promise<void>，签名为 onRegister(plugins)。
- 回调通过该数组删除、插入、追加或调整候选位置。
- 修改只作用于加载前草稿。全部注册处理完成后，Core 保存最终列表，并按该列表装配运行钩子和初始化；不把草稿引用当成后续安装接口。
- 最终列表以实际插件对象和数组顺序通过 `ctx.plugins` 只读暴露；插件可据此发现明确约定的能力，但运行期不能修改组合。
- 插件 id 是调用方自定义的稳定标识，不由 Core 生成 UUID、类名或 npm 包名。标识不等于对象实例；Core 不以同名 id 代替对象身份。
- after 只是关联/顺序意图的元数据声明。Core 不校验、排序、补装依赖或生成另一张执行图。数组是唯一加载和处理器执行顺序。
- 缺少关联插件时，当前插件自行选择补齐、移除自己、报错或降级；Core 不按 after 隐式级联。
- 注册声明只用于准备装配，不执行模型生成或业务工具。运行钩子的副作用不能借注册重排来倒序补执行。
- 注册遍历每次从当前草稿寻找尚未处理的对象；已删除且未处理的对象不执行，新增对象参与后续注册。同一对象的注册钩子只运行一次，最终列表中重复对象的运行钩子按每个位置参与，支持插缝式追踪；初始化按对象一次，避免重复注册工具。

## onInitialize 与工具初始化

- onInitialize(ctx) 使用该 Agent 长期保留的共享 Context，在本地 Agent 首次进入正常模型/工具循环前按顺序完成。
- 成功初始化后，同一 Agent 不重放本次初始化；并不表示后端历史为空，也不自动创建远端会话。
- 初始化失败阻止进入模型循环。初始化产生的外部副作用、幂等与释放由插件负责，不承诺事务回滚。
- 初始化期间工具注册表允许增加、删除和配置工具，最终名称必须唯一。初始化结束或抛错时固定注册表；默认工具循环仍使用同一 Registry 与 Core 工具入口。Registry 的原 Tool 读取与直接复用遵守 tool-runtime SPEC。
- 工具插件在 onInitialize 注册和调整自己的工具。默认注册行为可以由插件基类或辅助实现提供，允许覆盖或调用 super；TypeScript interface 自身不包含方法实现。Core 不在构造期另行注册同一工具集，也不强制继承某一基类。
- 提示词、后端资源或会话状态的准备由相关插件在初始化和后续运行钩子中协作完成；Core 没有系统提示词配置或自动说明追加规则。
- 恢复或 Fork 得到的插件装配进新 Agent 后，新 Agent 有自己的初始化。资源共享和重复初始化的处理由插件自己定义，不能复制父 Agent 初始化标记来跳过新组合准备。

## 每次执行与状态归属

- CTX 在 Agent 生命周期内保持同一对象；不因 run 新建或清空。每次运行的 Outcome 身份独立，插件用它关联接纳、错误与收尾，不用 CTX 身份代替。
- Core 不维护 active；并发接纳是可选策略。插件持有单轮状态时自行保护，并只释放自己接纳的 Outcome。
- onRunEnd 覆盖最终插件列表，不只覆盖已运行 onRunStart 的前缀。前置接纳插件 stop、合批或拒绝的调用也可能进入收尾；后续有状态插件必须核对自己接纳的 Outcome 后再释放。Core 不为每个插件维护另一份接纳表。
- onRunStart(ctx, input, outcome) 接收本次新输入和本次 Outcome 身份；onRunEnd(ctx, outcome) 是本次执行的 finally 收尾。两者不表示远端会话创建或销毁。
- model 生成实现拥有供应商请求、网络调用、流解析与最终产物构造。beforeModel 只接收 ctx；afterModel 接收共享可变的本轮结果，不接收生成器。
- Session 插件拥有消息列表、接纳记录、保存与恢复；可以在输入接纳、afterModel 和 afterTool 中维护相应消息。
- Core 不保存内部 Message[]，不在输入中接受完整会话历史，也不提供消息追加/替换接口。
- Session、模型、提示词、工具入口等插件通过 Context 的明确扩展或自身能力引用协作；能力字段及提交方式由对应插件合同定义。
- 钩子按顺序看到当前数据。Session 在自己所在位置保存当时可见版本；后续处理器可能继续修改，是否需要放在链末尾或保留其他版本由插件组合决定。
- 缺少跨轮记忆插件时，Core 不自动继承历史。完整输入处理与工具结果续接由实际插件组合提供；Core 只读取循环所需的最小控制产物，不通过 Session 名称或类型枚举决定能力。
- 压缩、存储、网络取消、恢复和接纳身份属于相应 owner。

## Fork 的组合边界

- Session 的 fork 是具体插件对象的实例方法，返回新的会话插件；它不创建 Agent、不接收 Agent 构造回调，也不替其他插件 Fork。
- Core 当前不提供 `agent.fork()`。完整 Agent Fork 由调用方或组合插件逐个取得所有参与插件的派生结果，再显式创建新的 Agent；普通运行不要求所有插件实现 Fork。
- 显式创建的子 Agent 遵守普通生命周期：第一次执行时先由 `onRegister` 处理调用方提供的候选数组，再由最终插件集合执行 `onInitialize`。Core 不识别其来源，也不因插件由 Fork 得到而跳过任一阶段。
- 每个插件按业务语义决定内部依赖是派生、复制还是共享；Core 不遍历依赖图、重写引用或调用任意对象的深拷贝。
- Fork 子插件的消息、存储回调、身份与后端引用语义由该插件负责，不进入 Core 循环。父插件的存储回调是否可共享必须由实际插件合同明确。
- 增减插件和工具时装配新的 Agent；只 Fork Session 并共享其他插件，不代表整组插件状态都已经隔离。
