# 工作流插件

工作流是普通 TypeScript 脚本，由 Host 负责加载、编译和执行。模型工具仅 workflow_run，接受命名库、脚本文件路径或一次性脚本三选一；模型通过常规文件能力保存，编写约定与检查建议放在插件 Skill。运行前强制校验，诊断作为工具错误返回；不先启动工作流。插件在工具可用时追加简短文档指引。工作流会话使用工作流模型钩子，并复用 Session 的输入接纳、历史和结果写入，不增加 Core 循环或第二份会话 owner。

脚本通过默认封装的 agent 创建空上下文工作者，可追加 Host 已注册的业务插件。具名方法使用 JSDoc @node 或 @phase 标记为方法节点；匿名回调可作为实现细节。Host 从同一 TypeScript Program 解析静态调用关系，并插桩记录实际调用实例与父子身份；作者不维护内部 ID 或另一份图定义。静态图不推断实际执行路径，运行时节点状态、重复调用与动态边必须来自调用事件。标签不改变业务控制流；具体编译、持久化和界面边界归 Host。

外层多轮历史只将 user/assistant 正文提供给脚本；内部 Agent 每个工作流回合重新创建，在同一回合中按脚本是否复用同一对象决定是否保留上下文。RAG 检索通过独立插件注入，数据连接与秘密仍在 Host。工作流停止取消脚本及其工作者，不保证撤销已发生的外部副作用。

持久化脚本源、输入和运行事实由 Host 拥有。自动图展示不自动执行代码；运行需要显式工具调用或人类操作，并遵守当前授权。部署 API 复用同一 Host 命令与会话，认证和监听属于应用服务，不属于插件。
