# Codex v2 记忆插件

## 来源与适配

基于 openai/codex 的 806d9732c974bc8a51b8317c1bd8985544fe627c；派生算法/提示词采用 Apache-2.0。结构为 memory.md 与 conversations/*.md。每个会话的标题由宿主提供；单次提取生成 description 和 summary，程序写入会话身份、源更新时间、JSONL 引用和稳定文件名。没有 raw_memory、MEMORY.md、skills 生成阶段。

## Owner 与原文

宿主提供可信 ownerId/conversationId、Chat JSONL 来源、状态存储和模型配置。每个存储操作按 ownerId 隔离。工具参数不接受 ownerId 或任意文件系统路径。sourceRef 定位原始归档，不承诺连续行范围已完整总结。来源消息标记 human/assistant/other-agent/context/tool；系统提示词、推理与注入的 memory 不作为人类证据。

## 两阶段与时序

每次主会话运行可触发独立后台整理；不等待整理后才回答。后台任务按 owner 隔离，持久化任务租约、令牌、失败退避、源版本水位与使用反馈。排除当前会话、活动会话、短暂内部 worker、关闭生成的会话。符合 idle/age 限制且来源变化的会话重新从原文生成摘要，不采用旧摘要加新消息的增量输入。

提取优先级为 Human > Final > OtherAgent > Commentary > Context > Tool；同层先选新内容，再按原顺序呈现，省略与截短必须明确。保留人类工具答复的问题。输入预算、工具结果和记录长度有界；摘要/description 脱敏。

每次后台模型请求都复用 Compaction 包的完整请求保守估算，计入系统指令、工具定义和累计回执；上限取本地预算、模型输入上限、上下文窗口扣除输出预留的最小值。提取阶段按可用容量减少来源输入。跨会话整理若无法容纳完整必要输入，则在网络请求前报告 input_budget_exceeded，保留已发布记忆和未处理笔记，不把静默丢弃条目作为整理成功。容量不足需调整模型或输入策略，不承诺任意小窗口均可完成整理。

成功空结果推进源水位并删除旧摘要；失败保留旧摘要、设置退避。过期任务不能凭旧令牌覆盖新结果。跨会话整理选择近期有用摘要，按使用反馈排序，输入变化清单和已有 memory.md；无变化且产物有效时跳过模型。独立整理 Agent 通过普通 Core 工具读取摘要和原文核验、发布候选全局文档。发布检查租约及输入版本，失败保留已发布全局记忆。原文读取是相对 Codex v2 的明确扩展。

追加笔记按持久化序号分批整理，每批最多 32 条、序列化输入最多 20 KB。成功发布才推进已处理水位，失败或失去租约不消耗笔记；未处理的尾部仍参与当前记忆可见性判断。既有笔记保留为原始记录，可通过有界 notes_read/notes_search 核对；不能每轮重新注入全部历史。单条超预算笔记先提供明确截断的预览，整理 Agent 完整读取该笔记后才可发布。

## 读取与纠正

共享插件注册 memory_list/read/search/note、conversation_list/search/read/send。每次运行加载当前用户全局文档，工具先暴露标题和 description，再按需读取摘要/JSONL。范围读取有界，关键词定位给原始行号和上下文；BM25 仅作为宿主检索排序增强，不冒称 Codex 原实现。显式记住/纠正/忘记通过追加笔记交给整理器；指定 conversationId 的忘记永久撤销该来源的记忆可见性，旧任务与旧摘要不能恢复。未指定会话的更正/忘记在整理成功前屏蔽旧生成文档并注入有界待处理笔记，不推断为删除所有原文。

记忆插件在 beforeModel 写入独立 RequestContextPlugin 的贡献；其公开 ChatSessionSource 适配器先委托现有 Session 接纳纯消息，再将临时上下文投影返回现有 Model。新增组合复用二者公开 hooks，不修改 Core、Model、Session 源码或其方法。临时记忆不写入原始历史。重试只复用已准备的原始输入，临时记忆重新读取当前值；不声称整个模型 wire 请求字节相同。用户身份和会话绑定在宿主，单轮状态使用 Outcome，Core 不增加记忆字段或周期任务。笔记幂等键由宿主用原 assistant 批次记录与 callId 解析；只有提供该解析能力时工具声明安全重试。

可信 binding 的 useMemory=false 时清除临时贡献并跳过自动全局读取和使用反馈，不能先读取存储再丢弃结果。工具的显式可用范围仍由宿主权限组合决定，不在运行中改动已固定的注册表。

正常工具执行与故障恢复复用相同的无规范化输入 schema 和回执格式化函数。已持久化的参数不再裁剪空白；模型可见回执统一脱敏并限制长度。

原文工具按完整物理行优先分页；超大单行提供明确 lineFragment 和 nextLine/nextOffset，调用方以返回坐标续读。startOffset 是该行脱敏视图的 UTF-16 位置，不切开代理对，不把片段伪装为完整行。回包预算计入 JSON 转义与维护条件；其他超大 JSON 回执采用有截断标记的结构预览，不在序列化后的 JSON 文本中间裁切。

## 程序与模型职责

conversation_send 的模型输入仅为目标 conversationId 与 content。宿主从已持久化的 assistant 记录和 callId 得到同一次调用的稳定身份，存储首次投递时随机生成消息 ID，并在同一个原子提交中保存去重记录和目标信箱。恢复重放同一次调用返回原消息回执；新的调用即使正文相同也允许产生新消息。模型不生成或维护幂等键。已确定的参数冲突作为工具错误闭合调用，不遗留无法恢复的 pending。

conversation_list 独立于摘要，按创建时间及会话 ID 稳定倒序分页，返回标题、可选 description 和原文引用；未摘要的空会话也可发现。原文检索检索标题与完整 JSONL，授权及撤销范围在排序截断之前生效，不能把摘要搜索未命中解释为没有历史。

整理开始前已存在的摘要滞后不阻断发布；发布校验比较整理开始与结束的原会话版本，仍拒绝运行期间变化的来源。纠正与忘记笔记形成持久化的内容维护水位：旧摘要在覆盖相关笔记前不可见，即使全局整理已经完成也不恢复可读。后续提取在单次摘要请求中应用相关纠正/忘记，并在成功后一起推进源版本和笔记水位；超预算或失败保留不可见状态。原始 JSONL 保留历史，显式读取时同时返回相关维护条件，不把保留历史等同于继续推荐旧偏好。

程序提供每条维护记录的 createdAt，不能以会话时间替代纠正时间。提取只纠正摘要中已有的对应事实，不把其他主题的维护要求写成该会话的事实，也不把维护事件归为原始会话历史。description 与 summary 遵循该会话用户使用的语言。

全局文档仍采用 Markdown。模型提供语义章节，程序添加 v1 与 What's in Memory 目录，从所选摘要的真实相对路径、标题及 description 生成有界入口；模型无需重建文件名或原文引用。读取工具允许使用程序提供的精确相对路径，禁止绝对路径、目录穿越和不存在的引用。目录空间不足时保留完整入口并通过分页工具发现其余会话，不截断路径或生成半条入口。

模型输入包含程序提供的会话创建与更新时间，以免从主题推测日期。提取和整理不得将参与讨论推断为实际参与、将单次任务要求推广为全局偏好，或从活动场地推断职业与学生身份。维护请求用于修改可保留内容，不作为会话历史复制；遗忘值也不能以“已遗忘”的形式继续写入正文。以上语义约束由真实模型验收检查，结构校验通过不代表事实准确。

## 验收

阶段二的数量上限只限制本轮归纳输入，不删除近期未入选的权威摘要。成功发布后仅清理不存在、撤销、关闭生成或超过未使用期限的来源摘要；未变化的近期落选摘要仍可读，并能在候选排名变化时重新入选。

纠正和忘记的即时屏蔽只影响读取投影，保留已发布全局正文供整理器保留无关有效事实；仅成功候选替换持久正文。使用计数写入属于非关键反馈，失败不能改变主回答的完成或会话收口。

摘要提取默认使用 Chat 严格 JSON schema，仅限制提取请求；宿主可明确选择 json-object 或 text 以适配不支持该能力的模型。结构化参数通过现有 Model 的 providerOptions 传递，所有模式均保留返回校验，不自动降级、重试或切换协议。跨会话整理使用普通工具调用，不继承宿主的 response_format。

维护记录保留完整历史，原文读取的附加条件超过 4 KB 时返回程序生成的 memory-notes:<conversationId> 虚拟引用。复用 memory_read 的行范围读取，按完整内容换行并限制每页大小；引用按可信 owner 和来源撤销状态检查。该引用不是第三类持久文件，不因历史笔记总量封锁原文。

真实 Core/Chat 请求证明上下文注入且不会出现在原始归档；超预算优先级、纠正、来源引用、长会话重生成、无变化跳过、失锁/并发/失败恢复、空结果、使用反馈、关键词与范围读取、跨用户隔离及跨会话消息持久化均通过公开合同验证。受控 HTTP 模型测试不代表真实模型语义效果。
