# 生产级 Agent 工作流设计参考

本 Skill 是给编写工作流的 Agent 使用的**经验指南和思考清单**。目的是在有需要时提醒容易忽视的生产环境问题，而不是要求每个任务遵守统一流程、生成设计报告或完成全部检查。

## 使用原则

1. **先做用户要求的事情。** 用户要生成代码就生成代码，要讨论架构就讨论架构，不为启用 Skill 增加额外流程。
2. **按场景取用。** 根据现有代码、需求和部署方式选择相关条目。确定不会出现的场景直接略过；不需要为每个问题写“不适用”说明。
3. **先读现有实现。** 能从代码、依赖能力或现有测试确认的问题，优先基于已有证据判断，不必重新实现验证程序。
4. **只提醒有实际价值的风险。** 对高影响、无法从代码判断的问题，可以建议测试或故障模拟；是否执行由任务要求、环境和成本决定。
5. **避免夸大保证。** 区分框架内置能力、应用配置、尚未实现的方案和经过测试的行为。设计建议不能表述为已经具备生产保障。

## 工作流选型提示

- **路径明确、可复用的业务处理**：优先 Workflow（工作流），让条件分支、并行汇合和状态边界可解释。
- **需要动态探索、规划和工具选择的任务**：可使用 Agent / Deep Agents；也可将 Agent 作为工作流中的一个节点。
- **以 LangGraph 为主要实现**：复杂状态流程优先考虑 Graph API；偏代码式编排时可以考虑 Functional API。
- **原生 TypeScript 工作流**：适合简单、灵活的业务编排。是否支持跨进程持久恢复以实际运行时能力为准，不自动继承 LangGraph 的保障。
- **普通确定性逻辑**：用函数或常规代码即可，不必强制封装成 LLM Agent。

## 可能值得留意的设计问题

- **节点与 State**：拆分职责，定义输入输出、分支和循环终止条件，避免并行更新覆盖彼此的状态。
- **持久化与恢复**：需要宕机续跑时，确认真实持久化后端、恢复到哪一个节点/任务边界，以及谁负责重新调度。
- **工具与副作用**：考虑超时、失败、重试、限流、结果未知；外部写操作注意幂等、查询确认或补偿。
- **权限与上下文**：注意工具授权、隐私数据、模型可见参数与运行时私有参数、检索证据的引用一致性。
- **运行与发布**：只有服务化或长期任务确实需要时，再考虑 Run API、版本兼容、日志追踪、监控与回滚。

详细条目按需查阅 [设计覆盖清单](references/design-checklist.md)。不要求全部勾选，也不要求向用户展示整张清单。

## 如何与官方 Skill 配合

这份 Skill 不复制 LangGraph 的完整 API 教程。涉及具体 API 时，优先使用已经安装的官方 LangGraph Skills，例如 langgraph-fundamentals、langgraph-persistence、langgraph-human-in-the-loop 和 langgraph-typescript-quickstart。没有安装的 Skill 不要假装读过，也不必为了本 Skill 自动下载。

本 Skill 只提供补充的架构经验；是否实际实现、修改或运行测试，以用户当前任务为准。
