# 生产工作流设计覆盖清单

这是**按需查阅的提醒库**，不是工作流生成的必经流程。41 项只是帮助发现可能遗漏的设计问题，不要求勾选、打分、逐项输出报告或实施测试。

先看工作流是否有对应能力，再决定是否关注：无并行则忽略并行合并；无外部写操作则忽略写入幂等；不要求跨进程恢复则无需强制配置持久 Checkpointer；未发布 API 则不必设计 API 运维。代码和现有测试已能说明的事项，不必额外验证。若只是开发一个简单示例，优先保持实现简洁。

只有用户明确要求详细审查或交接时，才考虑整理适用项、已知事实与待确认风险；不需要记录所有“不适用”条目。

## A. 需求与架构

- [ ] A01 是否需要明确输入输出 Schema、必填字段、数据大小及敏感字段边界？
- [ ] A02 如果要对外服务，是否需要约定响应时间、并发、运行时长、成本与降级目标？
- [ ] A03 固定步骤和动态 Agent 的职责是否清楚？确定性处理是否可以直接用普通代码？
- [ ] A04 如果流程复杂，节点是否方便独立理解、验证和复用？
- [ ] A05 如果存在分支、循环或多轮规划，是否有兜底路径和合理的终止限制？
- [ ] A06 如果存在并行写入 State，是否定义了合并规则并避免覆盖更新？
- [ ] A07 如果需要多轮检索或引用，证据和结果是否有可追踪的稳定标识？
- [ ] A08 如果工作流长期维护，关键模型、工具、提示词和数据版本是否有追溯办法？

## B. State / 持久化 / 恢复

- [ ] B01 如果保存或查询 Run，Run ID、Thread ID 以及用户/租户作用域是否清晰？
- [ ] B02 如果持久化 State，是否考虑序列化、数据体积、敏感字段以及后续版本演进？
- [ ] B03 如果要求进程重启后恢复，是否使用真实持久化 Checkpointer，而不只是内存保存？
- [ ] B04 如果存在恢复重放，是否清楚哪些节点已提交，以及未提交的副作用可能怎样处理？
- [ ] B05 如果并行分支需要恢复，是否理解框架的部分成功和 pending writes 语义？
- [ ] B06 如果有人在回路的审批，恢复时能否保留决定并校验审批作用域？
- [ ] B07 如果支持取消、超时或长任务，状态更新与资源回收是否合理？
- [ ] B08 如果要求宕机自动续跑，除 Checkpoint 外是否还有重新调度或领取机制？
- [ ] B09 如果存量 Run 可能跨版本恢复，是否考虑状态兼容、迁移或固定旧版本？
- [ ] B10 如果多 Worker 可能恢复同一 Run，是否有明确的竞争保护策略？

## C. 工具、外部副作用及安全

- [ ] C01 如果调用外部工具，是否区分可重试错误、永久失败、超时与结果未知？
- [ ] C02 如果依赖网络服务，是否有合适的超时、有限重试以及 429 的处理方式？
- [ ] C03 如果可能出现大量并发重试，是否考虑预算、限流或背压，避免放大故障？
- [ ] C04 如果存在外部写操作，是否需要幂等键、结果查询或补偿方案？
- [ ] C05 如果操作成功但响应丢失，是否考虑“结果未知”，而非直接重做？
- [ ] C06 如果工具有敏感权限，模型可见参数、运行时凭据及授权边界是否分离？
- [ ] C07 如果涉及高风险操作，是否需要人工审批，并绑定实际执行参数？
- [ ] C08 如果消费不可信输入，是否考虑提示注入、工具返回污染与数据越权？
- [ ] C09 如果工具结果较大或含敏感内容，是否需要截断、分页、结构校验或脱敏？
- [ ] C10 如果依赖可动态变化的 MCP 工具，断连、工具变化或 Schema 变化时如何处理？

## D. RAG / Agent 质量

- [ ] D01 如果检索受权限约束，文档、租户和索引范围是否在可信层检查？
- [ ] D02 如果使用 RAG，是否能区分无结果、索引失败、重排失败与超时？
- [ ] D03 如果需要引用证据，标识、去重与多轮引用是否可能混乱？
- [ ] D04 如果输出具有业务后果，低置信度、冲突证据和无法回答时如何处理？
- [ ] D05 如果需要衡量质量，是否已有适当规模的回归样本和检索/回答指标？
- [ ] D06 如果模型结果进入结构化流程，是否考虑格式错误、上下文过长或预算耗尽？

## E. 服务化运维

- [ ] E01 如果提供 API，是否考虑适用的鉴权、租户隔离、速率限制与请求幂等？
- [ ] E02 如果 API 运行长任务，Run 状态、取消、重连和结果查询是否有明确契约？
- [ ] E03 如果需要排障，日志和追踪能否关联关键步骤并避免暴露敏感数据？
- [ ] E04 如果有服务级目标，是否有足够的成功率、延迟、恢复与成本指标？
- [ ] E05 如果正式上线，是否有与业务重要程度匹配的告警、备份与回滚考虑？
- [ ] E06 如果准备做破坏性模拟，是否确认环境隔离且不会碰真实用户数据？
- [ ] E07 如果工作流可能持续运行或升级，是否考虑发布物版本与存量状态的关联？
